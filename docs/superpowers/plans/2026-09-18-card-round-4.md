# One-button card — Round 4: the screens

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person picks *card image* on the OS Builder's Machine tab, names the partitions and drops folders, archives and WHDLoad HDFs on them, presses one button on the Build tab, agrees to the Kickstarts ART offers, and gets a finished card image — with every size, every refusal and all four endings said in their own language.

**Architecture:** The card lives inside the existing four tabs (owner's decision 1). The Machine tab grows a destination choice (*Folder* · *Card image*) and, in card mode, a card section: size, image, Emu68 archive, the PFS3 driver line, and partition rows that take sources by drop, by `Add…` and by a row menu. Sizes and refusals come from a new read-only command (`card_os_measure`) that measures without staging, so the totals are live before anything is unpacked. The Build tab, in card mode, runs a second, card-shaped runner beside `useBuildRun`: the OS Builder's existing tree/updates/first-boot phases write into the session's scratch `tree/` (the user never sees that path), then `card_os_prepare`, then the Kickstart agreement, then `card_os_build`. The build reports its phase and count on a typed event, the job bar learns a fourth ending (`refused`), and every card refusal reaches the screen as a code plus typed parameters, so both catalogues can say it in Turkish.

**Tech Stack:** React 18 + TypeScript (`src/`), Rust (MSRV 1.93) for the five core/command changes, Vitest + Testing Library (jsdom for `*.test.tsx` only). No new dependency on either side.

**Spec:** `docs/superpowers/specs/2026-09-11-one-button-card-design.md` (§3, §5, §6, §7 Frontend, §8.5).

## The owner's decisions (2026-09-17/18)

1. **The card lives on the Machine tab** as a destination choice; the Build tab shows the card's phases when that choice is made. Not a fifth step, not a rebuilt `boot-card` lane.
2. **The card's system tree is built into the session's scratch folder and never shown as a destination.** `osinstall.destination` keeps its present meaning for the five screens that read it (T §1.2); a user who wants to keep the tree picks *Folder* instead.
3. **The build reports its phases.** A small Rust change emits phase and count, so the screen can say *"Bölümler: 4 812 / 9 216 dosya"* rather than nothing.
4. **Card refusals are Turkish.** Every card refusal reaches the screen as its `ART-*` code plus typed parameters, and both catalogues carry a sentence per code. Round 3's ruling that `CardSourceUnusable.why` is prose is **reversed**.
5. **The job bar gains a fourth ending, `refused`** (`core/jobs`), so a refused build is never called *failed*.
6. **`CardBuilder` and `VolumePreload` stay, behind power mode.** The one-button flow is the default; the manual screens are the advanced path, and every value they share with it is read from one key.

## Global Constraints

- **Technical complexity belongs in Rust.** A screen renders what a command answered; it never re-derives a size, a name rule or a refusal.
- **`src/lib` never renders a string**: a helper returns `Phrase { key, params? }` and the component calls `t()`. Both catalogues change in the same commit. Every new mapper is added to `phrase-keys.test.ts`'s import list.
- **One global drop listener** (`Layout.tsx` via `lib/dnd.ts`). Rows do not subscribe; they carry `data-card-row="<index>"` and read the outlet context.
- **Nothing changes unless the user changes it**: every remembered value goes through `src/lib/remembered.ts`'s guard, per release (Q2), and a late read never overwrites a key touched this run (ART-089).
- **Beginner mode only hides** (`usePowerMode`): no operation is disabled by mode, and nothing ART does changes with it.
- **A progress bar with an unknown total is forbidden**: say "N so far" or show nothing (`PhaseProgress`'s existing rule, T §1.4).
- **Endings stay distinct** — succeeded · refused · failed · stopped — in the phase row, in the job bar (Task 1) and in the operation log.
- `src-tauri/src/core/` stays platform-independent and free of Tauri; `core/cardos` remains the top of the card path (`core::independence` guards it).
- New `CoreError` variants and new job states get their own distinct code and join the tests that enumerate them.
- Test scratch in Rust: `let (_guard, dir) = crate::core::ScratchDir::pair(prefix, tag)`. Frontend tests: `// @vitest-environment jsdom` on line 1, an explicit `cleanup()`, mocks at the `@/lib/*` boundary (never `@tauri-apps/api`), and remembered state reset between tests (T §6).
- Every shell: `TMP`/`TEMP` on `E:\amiga\ProjeART\build\tmp`; never write to `C:`. Bash needs `export PATH="/c/Users/ismoz/.cargo/bin:$PATH"`. Redirect output to files under `E:\amiga\ProjeART\build\tmp\card-r4\`; never pipe a command whose status matters.
- Per task: the touched Rust modules (`cargo test --lib <path>`) and the touched frontend files (`pnpm vitest run <file>`), plus `pnpm lint` whenever TypeScript changed, `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` whenever Rust changed. The whole suite only in Task 13.
- Red first: every new test seen failing for its stated reason before the implementation; a mutation for every guard that matters; survivors disclosed.
- Commits: `git branch --show-current` must print `art-card-round-4`; stage by name; message via file with `git commit -F`; end with `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`; run `python scripts/control-byte-sweep.py` (unpiped) before committing, and the two scratch sweeps when Rust test code changed.
- **The screen may not out-claim the core**: if Rust says a partition was not filled, no row above it says it was.

### Task 8: The card section — partitions, sources, sizes, overflow
