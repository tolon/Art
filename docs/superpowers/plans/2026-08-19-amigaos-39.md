# AmigaOS 3.9 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ART builds an AmigaOS 3.9 distribution tree from the user's own CD, and that tree boots.

**Architecture:** `core/osinstall` is already written against a `MediaSource` trait, and `AdfSource` is one implementation of it. This adds a second — `CdSource`, over ART's existing oracle-verified ISO reader — teaches media discovery to recognise a disc, and ships a second recipe as data. No engine changes: the recipe format already says *volume name plus a path inside it*, which is exactly what a CD needs.

**Tech Stack:** Rust (`core/iso`, `core/osinstall`, `serde`), `include_str!`-embedded recipe JSON, `#[ignore]`d environment-gated hooks for the user's own copyrighted media.

**Spec:** [../specs/2026-08-19-amigaos-39-design.md](../specs/2026-08-19-amigaos-39-design.md)

## Global Constraints

- **`src-tauri/src/core/` is platform-independent.** No `use tauri`, no Windows APIs, no network.
- **Never read a whole image into memory.** The 3.9 ISO is 469 MiB. `IsoImage` already reads a sector at a time; nothing here may collect the disc.
- **ART ships no Amiga content.** Every test fixture is synthetic and built in a tempdir. The one exception is an `#[ignore]`d, environment-gated hook that runs against the user's own media — the shape `run_the_real_engine_against_the_users_own_media_when_asked` already uses.
- **A recipe's paths are human-typed data.** Every `/`-separated segment of `from` and `to` goes through `core::volume::write::dir::check_name`, and nothing may start with `/` or contain `..` — `recipe.rs::validate_path` already enforces this and must keep doing so for the deeper paths a CD needs.
- **No two components may claim the same destination** without one declaring an `overrides` relationship; a test asserts it over every shipped recipe.
- **Unused imports and variables are compile errors** in this crate (only `dead_code` is allowed).
- **Doc comments explain *why*, not *what*.**
- **Verify with:** `cd src-tauri && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` (twice — ART-059), and `pnpm lint && pnpm test`.

The shape, with the fields you must read from `IsoEntry` yourself:

```rust
pub struct CdSource {
    image: IsoImage,
    entries: Vec<IsoWalkEntry>,   // the whole disc, walked once at open
}

impl CdSource {
    pub fn open(path: &Path) -> CoreResult<Self> {
        let image = IsoImage::open(path)?;
        let walk = image.walk()?;
        Ok(Self { image, entries: walk.entries })
    }
}

impl MediaSource for CdSource {
    fn volume_name(&self) -> &str { self.image.volume_name() }
    fn entry(&mut self, path: &str) -> CoreResult<Option<MediaEntry>> { /* lookup in self.entries */ }
    fn walk(&mut self, path: &str) -> CoreResult<Vec<MediaEntry>> { /* prefix match on entries */ }
    fn read(&mut self, path: &str) -> CoreResult<Vec<u8>> { /* image.read_file(extent, bytes) */ }
}
```

Three decisions to make deliberately and record in doc comments:

- **The walk is taken once, at `open`.** `IsoSource` in `core/iso` already does this and says why: a disc's tree does not change under ART's feet. Follow it rather than walking per call.
- **Protection bits.** ISO9660 carries no AmigaDOS protection. Answer with whatever `core/volume`'s convention calls "nothing set" rather than inventing bits — and say in the doc comment that the value is absent from the medium, not measured, so nobody later reads it as a fact.
- **`walk("")`** must mean the whole disc, because the trait says so and a recipe may use `from: ""`.

Then add `pub mod source_cd;` to `core/osinstall/mod.rs`.

## Task 2: Media discovery finds a disc

**Files:**
- Modify: `src-tauri/src/core/osinstall/scan.rs`
- Test: inline, beside the existing `find_media` tests

**Interfaces:**
- Consumes: `CdSource::open` from Task 1; `AdfSource::open`; `FoundMedia { path, volume_name }`.
- Produces:
  ```rust
  pub enum MediaKind { Floppy, Disc }              // serde kebab-case if it crosses the wire
  pub struct FoundMedia { pub path: PathBuf, pub volume_name: String, pub kind: MediaKind }
  pub fn open_media(found: &FoundMedia) -> CoreResult<Box<dyn MediaSource>>;
  ```

**The problem this solves.** `find_media` opens every file with `AdfSource::open` and keeps what opens as a bare AmigaDOS volume; a `.iso` fails that and is skipped. `FoundMedia` then carries only a path and a volume name, so whoever opens it later has no way to know which reader to use. Adding the kind at discovery is what lets one factory answer.
