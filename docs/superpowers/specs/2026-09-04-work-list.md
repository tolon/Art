## The sequence

Five items, and the order is the same rule as before: what changes what ART
can do, before comfort.

### 1. 🟡 A release update is layered, and ART cannot say so

*The whole of what is left of old item 8. Not a JSON file — a concept.*

`extra_media_folders` is a **set**, and its refusal is right for one: two
disks of one name in folders somebody assembled are an ambiguity ART must not
resolve by click order. Measured on the owner's own material 2026-08-25: 63
volumes across their 3.2.1 and 3.2.2 folders, and both carry a
`DiskDoctor.adf` of exactly 901 120 bytes under the same volume name with
**different SHA-256s**. So a 3.2.2 install is refused today, correctly and
uselessly.

What is missing is that "the base, then the update" is an **order the release
states**, not one the user clicked. Expressing it needs a concept ART does not
have.

**Done when** a layered source can be expressed and the owner's own 3.2.1 +
3.2.2 folders install without a refusal, with the later disk winning *because
it is later* and the log saying which one won and why. The 3.2.2.1 and 3.2.3
recipes stay unwritten until their media is in hand — a recipe written from
volume names read off a web page is exactly how a tree that was AmigaOS 3.5
shipped as 3.9 ([ART-159](../../ISSUES.md#fixed)).

*Also measured and worth carrying into the design: the update ships two
locales the base set does not have (`Locale3.2.2-CZ` at 283 files,
`Locale3.2.2-RS` at 240 — whole locales, not overlays), and its own Kickstart
is 47.111 with a `HowToInstall` that recommends softkicking the modules rather
than replacing the ROM.*

### 2. 🟡 SD-2 G10 wave 2 — where `igame.data` goes

*The last gap SD-2 names. The format is done; the destination is not.*

`core/gameindex/igame.rs` writes the file to iGame's own source, and it is
verified: 15 tests, eight mutations, eight fell. But **"beside each slave"
cannot be done for this collection** — 2 815 titles, of which 1 697 are
`whdload-hardfile`, 1 016 `floppies`, 102 `hardfile` and **zero drawers**. The
slaves are inside the hardfiles.

Two routes, neither built, and they are not equivalent:

1. **Into the hardfile**, beside the slave, through `core/volume/write`. Writes
   into the user's own image, so it is the pipeline's full ceremony.
2. **Into a distribution's own Games drawer**, for a build that unpacks
   WHDLoad titles onto the volume ART is making. Nothing existing is touched.

**Done when** one of the two is chosen with a reason, built, and a real
`igame.data` is read by iGame — or, if the answer turns out to be neither,
when that is written down the way the AGS assessment was.

### 3. 🟡 SD-3 G14 — the half that is not the network

*Wallpaper and prefs. The network half closed 2026-08-24.*

G14 is "it is **mine**": wallpaper, WiFi, prefs and Startup-Sequence, each
edited in place. `startup.rs` was already done and the keymap selection is its
first real user; `core/amiganet/` closed the WiFi and networking half against
the owner's own stack's C source.

**Wallpaper is new scope and is not designed.** Which picture formats, where
they go on the volume, what writes the prefs that point at them, and what
happens to a wallpaper the user already has — none of it is decided, so it is
a design round before it is a build round.

**Done when** the scope exists as a written design; building it is a separate
item after that.

### 4. 🟡 SD-5 G13 — the profiles half

*The planner closed 2026-08-24; this is the other half.*

`core/distro/registry.json` holds five entries — `caffeineos`, `coffinos`,
`amikit`, `art-baseline-32`, `art-baseline-39` — and **every one is
`available: false`**, which is checked and correct rather than pessimistic.
Three of them are somebody else's images and ART may claim nothing about a
layout nobody has opened.

**Done when** a real distribution image has been obtained by the owner and
read by hand, its layout written into the profile, and one card planned from a
named distribution end to end. **ART never downloads a distro image** — the
`homepage` field is where the user goes.

### 5. 🟡 Collection wave C — verification, not code

*What remains of old item 18.*

Four rows in [FEATURES.md](../../FEATURES.md) are amber for the same reason:
the engine exists and nobody has driven the screen. A hand-attached picture,
the Collection's detail panel, cover art in the listing, and Play a catalogued

**Done when** each has been driven against the owner's own 2 815-title
catalogue and either flipped to ✅ or given a defect number.

- **A card flashed and an A500 booted.** SD-1's last item and the bar for 1.0.
  Not code; the owner does this part, and it runs in parallel with everything
  above. The software side is complete — what is missing is a microSD card, a
  USB reader and an HDMI cable, the last plugged in *before* power.
- **[ART-118](../../ISSUES.md)** — the OS Builder's install screen has never
  been driven past a smoke test; headless Chrome and Edge both crash with an
  access violation. Needs `pnpm tauri dev` and a person. Fold it into whichever
  UI round comes first.

  screen. Fold into any round that changes rendered text.
- **[ART-166](../../ISSUES.md)** — no password bypass; the owner's standing
  decision, re-researched 2026-08-25 and unchanged. The Amiga-side route works
  and is what remains of it.
- **[ART-117](../../ISSUES.md)** — left deliberately; `hst-imager` is the
  named fallback and the refusal says so.
- **[ART-235](../../ISSUES.md)** — `scratch-counter-sweep.py` calls a
  thread-id-keyed helper wrong. Small, and it belongs to whoever next touches
  the sweep rather than to a round of its own.
- **The other nineteen 3.9 locales.** The shape is mechanical now; shipping
  them uninvited is ART answering a question the release asks.
- **SFS** — deferred by the owner's decision; see the head of
  `ART-brief-sfs-integration.md`.
- **`OsInstall.tsx`'s remaining split** — no user-visible value, real risk.
  Wait for a round that needs it.
- **The AI layer** — moved to v2 on 2026-08-24.
- **DMS, ADZ, HDZ, dircache, snapshots, resize/clone/repack, Gotek bulk, raw
  device writes, image compare, the workflow wizard, file associations, tags
