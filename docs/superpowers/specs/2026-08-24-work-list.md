### 7. ✅ `.vhd` output beside `.img`, and saying what a file is · *done 2026-08-24*

A 32 GiB card image costs 32 GiB today. Now with evidence beyond "the imager
offers it": the owner's `AmiKit.hdf` is 1 200 776 704 bytes beginning
`conectix` — a **dynamic VHD wearing an `.hdf` extension**, which is what one
shipped distribution hands its users. Two halves: ART should **write** a
`.vhd`, and `core/detect` should **say** a `.hdf` is really a VHD rather than
mis-reading it as a hard-disk image.

**Half two done 2026-08-24.** `core/vhd.rs` reads the 512-byte footer — the
format checked against libyal's `libvhdi` documentation, VirtualBox's
`VHD.cpp` and Microsoft's own notes rather than recalled. Detection looks in
**two** places because the specification puts the footer in two: a dynamic or
differencing image keeps a copy at offset 0, a fixed one only at the end.

**The two kinds get two answers, and that is the design.** A *fixed* VHD is a
raw image with 512 bytes appended, so every ART reader works on it unchanged
and it keeps every offer an ordinary image has. A *dynamic* one does not store
its data at offset 0 at all, so it is kept away from the Hard Disk Studio and
WinUAE — the same narrowing `is_lha` makes inside `is_archive`, and for the
same reason: an action that exists to fail (§46, §89). **It would have failed by
saying "this hard disk has no partition table"** about a disk that has one —
true about the bytes at offset 0, wrong about the disk. Hex and Collection
stay, so it is not a dead end (§91): hashing works whatever is inside, and raw
bytes are what somebody looking at an unopenable container wants.

The checksum is computed and **reported, never used to reject**: ART has one
real VHD to check the arithmetic against and it belongs to the owner. A
permanent `#[ignore]`d hook (`ART_VHD_IN`) is what will settle it.

17 tests. Nine mutations, nine fell — fixed and dynamic transposed, every kind
claimed to start at offset zero, the checksum no longer skipping its own field,
the length check weakened, little-endian instead of big, a fixed footer at
offset 0 accepted, the whole check skipped, the raw-studio narrowing removed,
and a fixed VHD narrowed along with the others.

**Half one done too, 2026-08-24, and the premise was measured first.** The
item said a 32 GiB card image costs 32 GiB; `build_card`'s own doc comment said
the opposite (*"`set_len` on NTFS costs nothing and takes no space"*).
`SetLength(2 GB)` on the owner's NTFS consumed **exactly** 2 147 483 648 bytes
and `fsutil` said the file was not sparse, so the item was right and the
comment was [ART-230](../../ISSUES.md).

`core/vhd/write.rs` writes a **dynamic** VHD — chosen over marking the file
sparse because `FSCTL_SET_SPARSE` is a Windows API call `core/` may not make,
and because a VHD's saving survives being copied to another machine where
NTFS sparseness does not. A destination ending `.vhd` gets one; anything else
is still the raw image every card writer takes, and **both go through one
`lay_out`**, so the two cannot drift apart in what they write.

`read_card` understands one too — without that, §92's VERIFY step would have
been verifying nothing.

**Verified by something that is not ART**, which is `core/card/build`'s own
rule: `scripts/vhd-oracle-check.py` writes an image and reads it with
Microsoft's `Get-VHD` and `Test-VHD` from the Hyper-V module. Every field
agrees — VhdType Dynamic, Size 34 359 738 368, FileSize **6 360 576**,
BlockSize 2 097 152 — a **5 402×** saving. Not in CI: the module is not on a
GitHub runner.

Eight mutations, five fell at once and **three survived**, all three because a
test was missing rather than because the code was safe: a second write to an
already-allocated block landing on its own sector bitmap, `open` accepting a
fixed image, and the block-count bound. All three now have one, and all three
fell on the re-run.

**The matching half is built.** `RomInfo::whdload_crc16` is computed at
`identify_rom`, where the decoded bytes already exist, and `core/rom/offer.rs`
answers *which of the images this title will accept do you already have?* —
matched on the checksum a slave declares, never on a filename. Four endings
kept apart: `Supplied`, `Encrypted` (a licensed ROM whose `rom.key` is absent
is a file the user **has**), `NotHere`, `Unmatchable` (the `$ffff` sentinel).
One of three alternatives is enough, which is ART-137's lesson applied.

**Nothing in `offer.rs` writes a file**, and a test shows that rather than the
doc claiming it.

**The placing step and its screen landed the same day.** `core/rom/place.rs`
carries out one agreed placement — never a title's worth. The name comes out of
a downloaded binary so it goes through `safe_join`; a licensed ROM is written
**decoded**, because copying an Amiga Forever file verbatim produces a card
that looks right and does not work. Three endings, and `Occupied` is refused
rather than replaced. The screen sits in `TitleDetail.tsx` beside the sentence
that already said what the title needs, and without a system volume it asks for
one instead of offering a button that cannot work.

15 tests over the two halves' new code. Eleven mutations, ten fell; the
survivor is disclosed in the source.

### 12. 🟡 SD-2 G10 waves 2 and 3 — launcher metadata · *the format is
built; where it goes is now a measured question*

Wave 1 (the game index) landed 2026-08-17. Wave 2: `igame.data` beside each
slave, drawer extraction from a hardfile, `games.json`. Wave 3: AGS export.
This is the last gap SD-2 names.

**The format is built and verified against iGame's own source**
(`core/gameindex/igame.rs`, 2026-08-24). `MrZammler/iGame`'s
`fsfuncs.c::getIGameDataInfo` and `funcs.c`'s calls to it were **read**, and
five of the six rules would have been got wrong by writing what the format
looks like from the outside — each producing a file iGame silently ignores:

- **the line buffer is 64 bytes**, and a longer line is *split* rather than
  truncated, so the tail arrives as the next line where an `=` inside a long
  title is parsed as a key;
- keys are matched with `strcmp`, so exactly lower case;
- **nothing is trimmed** — `title = X` yields the key `"title "`;
- `year` and `players` are taken only when `isNumeric`;
- **`exe` is rejected when it contains `.slave`**, which is the trap, because
  the obvious thing to put there is the slave.

An existing file is **edited, not regenerated** (CLAUDE.md's config rule: iGame
ignores unknown keys, so a user may keep their own in it), and a value that
will not fit is left out and **named** rather than shortened. 15 tests; eight
mutations, eight fell.

**But "beside each slave" cannot be done for this owner's collection, and that
is measured rather than argued.** Counted over their own catalogue on
2026-08-24: **2 815 titles — 1 697 `whdload-hardfile`, 1 016 `floppies`, 102
`hardfile`, and zero drawers.** `Media::WhdloadDrawer` was removed by
[ART-147](../../ISSUES.md) because the shape was wrong. The slaves are
**inside** the hardfiles.

So the remaining work is not "write the file", it is one of two routes, and
neither is built:

1. **into the hardfile**, beside the slave, through `core/volume/write` — a
   `whdload-hardfile` is a bare FFS volume ART can already write.

   **Measured before anybody decides**, on all 1 697 of the owner's own images
   (`igame::free_bytes_in_hardfile`, read-only): **every one read without
   error**, the median has **43 008 bytes free** against a file of a few dozen
   bytes, and **148 have less than a kilobyte** — many exactly zero. So the
   route is open for about **1 549** titles and closed for **148**, which is a
   distinct ending rather than a failure.

   **It is still a decision, not a task**: this writes into somebody's game
   files. It wants the same shape ART-130 got — a proposal, a confirmation and
   a backup policy — and the owner's word before any of it;
2. **into a distribution's own Games drawer**, for a build that unpacks WHDLoad
   archives rather than carrying self-booting images — the ClassicWB/HstWB
   shape, which this collection is not.

Drawer extraction from a hardfile, `games.json` and the AGS export are
untouched.

**One number worth carrying elsewhere**: **966 of the 2 815 titles declare a
Kickstart**, which makes [ART-130](../../ISSUES.md) — finished the same day —
apply to a third of the collection rather than to a handful.
